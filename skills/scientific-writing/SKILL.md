# 科学写作（Scientific Writing）

## 0. 唯一判据

**每个数字都能回答「口径是什么」，每个结论都能回答「它推不出什么」。**

缺一项，就不是科学写作，是叙事。

**REQUIRED BACKGROUND:** 计算或报告统计量前先加载 `experiment-statistics`（点估计 / 区间 / 分辨率 / 口径）。
**REQUIRED SUB-SKILL:** 术语按 `term-discipline` 执行。

## 1. 数字的七要素

任何进入结论的数字必须带齐：

| # | 要素 | 例 |
|---|---|---|
| 1 | 单位 / 量纲 | 写「个百分点（pt）」；水平用 %，差值用 pt，不混用 |
| 2 | 分母 | 「归属成功的行」，不是「全部行」 |
| 3 | 聚类层级 | bot 级 / 请求级 / 样本级 |
| 4 | `n` 的定义 | 入组单元总数，还是评测条数 |
| 5 | 时点 | `[实测 2026-11-06]` |
| 6 | 不确定性 | 区间 / 标准误 / 分辨率；没算就写「未算」 |
| 7 | 来源 | 命令 / 文件 / `file:line` |

示例数字必须标「示例」；**未测的量不得给数字**，写「未测」或留空。禁止「先写个数字占位」。

报告类文档：关键数字表加一列「来源」（文件 + 节 / 命令 + 日期，可带 `[转引 YYYY-MM-DD]`）；表内每个数字都要能指到来源。报告落盘 `docs/reviews/`（kb type `reviews`，默认 `final`），生命周期交给 `knowledge-base`。

## 2. 主张四元组

关键结论一行四列；只写前两列视为不合格：

| 主张 | 证据（等级 + 日期） | 支撑范围 | 越界即错 |
|---|---|---|---|
| 分桶原语与 Java 参考实现一致 | `[转引 2026-09-29]` 7/7 向量 h1/h2/n 全等 | 给定向量集上的**原语**逐位一致 | 推不出 assign 最终分组一致；推不出真实流量分布一致 |

写报告时，结论区必须有**至少一张四列表**（主张 / 证据 / 支撑范围 / 越界即错）；只写主张与证据 = 不合格。结论很多时，至少前 3 条关键结论进表。

## 3. 证据等级

- **断言级**：`[代码事实]` / `[提案]`（见 `writing-docs` skill 的 `references/evidence.md`）
- **文档级五档**：`[实测 YYYY-MM-DD]` / `[转引 YYYY-MM-DD]` / `[设计]` / `[假设]` / `[未验证]`
- **环境级**（工程仓建议）：`E0` 静态可复现 / `E1` 本机可执行 / `E2` 需 GPU 或专用环境 / `E3` 需下游或线上
- `[假设]` **不得被下游当实测引用**，禁止写进代码或配置当默认值
- `E2/E3` 的断言只能出现在「待验证」节，写清待跑命令与判据；不允许出现在「已验证 / ✅」后面

## 4. 动词强度匹配证据

区分四层：**观察 / 估计 / 解释 / 推测**。

- 观察：「本次运行输出 X」
- 估计：「在 n=… 的样本上，X ≈ …（95% 区间 …）」
- 解释：「这与机制 M 一致」（不是「证明 M」）
- 推测：「如果 …，可能 …」（必须给条件与反例）

禁止：把「不显著」写成「无差异」或「证明无效果」；把「理论上可测」当成「现在能出数」；把某个维度上的局部优势写成整体结论。

## 5. 可测性三态 + 负面清单

| 记号 | 含义 | 要求 |
|---|---|---|
| ✅ | 可测 | 给证据或复算方式 |
| ⚠️ | 条件可测 | 写明条件 |
| ❌ | 不可测 | 写明否决线：A 反事实不可得 / B 分析单位 ≠ 随机化单位 |

每个 ❌ 必须配「**被明确否决的近似做法**」表，逐条写为什么不行。禁止用改名蒙混（把 bot 级结果改叫「人均」）。

## 6. 事前声明 + 固定样本 + 单次读出

统计判定必须事前写清四件套：**指标 / MDE / 停止规则 / 签字人**。

- 跑满固定样本（或固定时限，先到者）后**一次性读出**
- 禁止边跑边看、看到显著就停、事后倒推 MDE
- 「显著」≠「可靠」：给出阈值处检出力这类反直觉数字

## 7. 测量 ≠ 判定

给一张归属表：这件事归谁（工具 / 分析方 / 业务 / 管理层），并明写本工具**不做**哪些判定。

- 工具负责：发生了什么、什么能被测
- 分析方负责：够不够、意味着什么
- 结论不得超出设计、人群与不确定性允许的范围

## 8. 可复算

文档里每个关键数字，必须能用文档内附的最小脚本复算：

- 标准库，无第三方依赖
- 每条关键数字配 `assert`
- 标注「断言通过日期」
- 失败日志与阴性结果保留，不选择性省略

## 9. 规范句与结论句的可判真性

完整方法见 `references/clause-check.md`。四条最常用：

1. **一个 clause = 一个可独立判真的实现点或断言**；对称句（「同样」「both directions」「symmetric」）必须双侧编号、分别验证
2. **量词与辖域显式**：每个 / 整场？在哪里重置？与其它计数的关系？用文档自己的估算数字做交叉算术
3. **条件守卫两侧都执行**：`若 P 则报错` 不能嵌在 `if P:` 内，否则 ¬P 分支永远不触发
4. **断言反空转**：每个测试必须能回答「什么情况下会红」；有 `or` 兜底、期待异常永不抛 = placebo

finding 写成五段：Location / Evidence（引原文）/ Why / Why-the-test-missed / Fix（选项 + 推荐）；编号稳定，撤回项保留并划掉。

## 10. 已知局限与未验证事项

必须专节写，逐条写**影响**（「这会怎么害到读者」），不是「仍有不足」。

## 11. 交付前自查

- [ ] 每个数字七要素齐全（报告里含「来源」列）
- [ ] 关键结论有四元组
- [ ] 观察 / 估计 / 解释 / 推测已区分
- [ ] 不可测项有否决线与负面清单
- [ ] 事前声明、固定样本、单次读出
- [ ] 测量 vs 判定边界表
- [ ] 关键数字可复算
- [ ] 阴性结果保留
- [ ] 规范句逐 clause 可判真
- [ ] 已知局限写了影响

## 12. 常见错误

| 错法 | 后果 | 改法 |
|---|---|---|
| 差 1.4% 写成「差 1.4%」 | 水平与差值混用 | 写「差 1.4 个百分点（pt）」 |
| 用请求数当 `n` | 标准误被低估，MDE 被低估 | 用声明的随机化单元 |
| 摘要没给的数字补一个 | 编造污染不可恢复 | 写「未给出」或留空 |
| 不显著写成「无差异」 | 把噪声当结论 | 报区间与分辨率 |
| 只报好消息 | 记录失真 | 阴性 / 失败结果保留 |
| 「已验证」但没命令 | 假证据 | 标 `UNVERIFIED(E2)` 并写待跑命令 |
| 在配置里写假设值 | 后来者当实测 | 假设只进文档，标注并给重开条件 |
